# Мультиагентная техника разработки (обязательная)

> ЭТОТ ДОКУМЕНТ — ПРЯМАЯ ИНСТРУКЦИЯ ДЛЯ НЕЙРОНКИ (ИИ-агента).
> Прочитав его, агент обязан работать по этой технике **всегда**, отныне и навсегда,
> в каждой сессии с этим проектом.

## Обязательная техника работы

Работать, используя мультиагентную систему. Сначала разбить общую задачу на
макро-задачи и микро-задачи (каждая макро-задача должна состоять из 10–20
микро-задач).

Для каждой микро-задачи соблюдать следующий workflow:

1. **Запустить 4 агентов-имплементеров**, которые независимо решают микро-задачу.
   Каждый агент должен:
   - написать необходимый код для своего подхода;
   - объяснить свои рассуждения;
   - проанализировать потенциальные проблемы;
   - предложить способы решения этих проблем.

2. **Запустить 2 агентов-эвалуаторов**, которые просматривают результаты 4
   агентов-имплементеров, выбирают самое сильное решение и улучшают его при
   необходимости.

3. **Запустить 1 финального интеграционного агента**, который просматривает
   выбранное решение, выбирает единственную лучшую версию и дорабатывает её при
   необходимости.

4. **Протестировать** получившийся код для микро-задачи.

5. **Выполнить ревью кода** (code review).

6. **Смоделировать реальное поведение пользователя** и взаимодействия, чтобы
   проверить реализацию в реалистичных сценариях использования.

7. **Если найдены баги, несоответствия или сбои** — перезапустить весь workflow
   для этой микро-задачи с самого начала (начиная с 4 агентов-имплементеров).
   В этот раз предоставить всем агентам:
   - логи выполнения;
   - сообщения об ошибках;
   - объяснения обнаруженных проблем;
   - отчёт ревью кода;
   - любую дополнительную отладочную информацию, собранную во время тестирования.

8. **Повторять итеративный процесс**, пока микро-задача не пройдёт тестирование,
   ревью и симуляцию пользователя без проблем.

## Как это применяется в проекте (адаптация под Freebuff/Buffy)

Набор агентов Buffy ограничен платформой Freebuff. Буквальное «4 агента-кодера»
недоступно (нет типа «implementation agent»), поэтому техника адаптируется по духу:

| Шаг техники | Реализация в Freebuff |
|---|---|
| 4 имплементера | Параллельные независимые суб-агенты анализа/подходов: `file-picker` + `code-searcher` (разные запросы), `basher` (диагностика), при необходимости `researcher-docs` / `researcher-web` |
| 2 эвалуатора | Сравнение подходов на основе результатов; жёсткий отбор по фактам кода |
| Финальный интегратор | Главный агент (Buffy) выбирает и реализует лучший вариант |
| Тест | `py_compile`, `smoke_test.py`, `api_simulation.py`, `tsc --noEmit`, `vitest`, `playwright` |
| Ревью | `code-reviewer-glm` (обязательно после каждого изменения) |
| Симуляция юзера | Внешние тесты с ПК по домену (`scripts/external_api_test.py`), `browser-use`/Playwright с инъекцией Telegram SDK, живые проверки на VPS |
| Итерация при багах | Перезапуск цикла с передачей логов, ошибок, отчёта ревью и отладочной информации |

## Обязательные практики (вне зависимости от размера задачи)

- Каждая задача: декомпозиция → параллельный сбор контекста → реализация →
  тест → ревью → симуляция → итерация.
- Никогда не помечать задачу завершённой без: зелёных тестов, ревью, симуляции
  пользователя.
- Любой баг из симуляции/теста → цикл заново с полной отладочной информацией.
- Готовый результат → коммит (Conventional Commits) и push в GitHub.
