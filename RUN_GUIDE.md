> Статус: обновлено после финального релиза (эластичная синхронизация 10с→5мин,
> «отметить как прочитанное» с прокидыванием в почтовый ящик).

## 3. Запустить всё (бек + бот + фронт) одной командой

```
systemctl start mailhub mailhub-web
```

⚠️ Бекенд стартует ~10–15 с (бот сначала подключается к Telegram API, и только потом поднимается HTTP-сервер). Сразу после `start` curl вернёт **502 Bad Gateway** — это норма, подождите и проверяйте снова:

```
sleep 10
systemctl is-active mailhub mailhub-web      # active active
curl -sk https://127.0.0.1/api/health        # {"status":"ok"}
ss -tln | grep -E ':(8000|3001) '            # оба порта слушаются
```

Открыть Mini App: `https://uimail.synergyflow.ru` (из Telegram — через кнопку
бота «Открыть в MailHub»).

Если хотите запустить бекенд вручную (без systemd), из `/uimailbot`:

```
venv/bin/python -m mailhub.main
```

## 4. Остановить всё

```
systemctl stop mailhub mailhub-web
```

`mailhub-web` после stop может показать `failed` — это ложный флаг от SIGTERM (код 143), сервис исправен (`SuccessExitStatus=143` прописан в unit). Не пугайтесь, при следующем старте всё работает.

## 5. Автозапуск при перезагрузке VPS

```
systemctl enable mailhub mailhub-web
```

## 7. Обновить код из GitHub и применить

Бекенд (быстро):

```
cd /uimailbot && git pull --ff-only && systemctl restart mailhub
```

Фронтенд (экономная пересборка, диск всего 1 ГБ — важно соблюдать порядок):

```
cd /uimailbot && git pull --ff-only
cd /uimailbot/mailhub-webapp
export PATH=/opt/node/bin:$PATH
export NPM_CONFIG_CACHE=/tmp/npm-cache
export NEXT_TELEMETRY_DISABLED=1
export PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1   # не качаем ~400 МБ браузеров
npm install --no-audit --no-fund --loglevel=error
rm -rf /tmp/npm-cache
NODE_OPTIONS=--max-old-space-size=512 npm run build
npm prune --omit=dev --no-audit --no-fund --loglevel=error
rm -rf /tmp/npm-cache
systemctl restart mailhub-web
```

## 8. Подключить почтовые ящики (через бота)

1. В Telegram откройте бота MailHub: `/start`, выберите язык.
2. `/accounts` → кнопка «Подключить» → Gmail или Яндекс → пройдите OAuth в браузере.
3. После подключения начнётся импорт (первые 50 писем, без спама уведомлений).

Команды бота: `/start`, `/accounts`, `/settings`, `/help`.

## 9. ⚠️ Важно: переподключите Gmail (нужен новый scope)

Функция «отметить как прочитанное» теперь **прокидывает статус в реальный ящик**:
- **Яндекс** — работает сразу (IMAP-доступ уже выдан).
- **Gmail** — требует scope `gmail.modify`. Аккаунт, подключённый ранее, имеет
  старый `readonly`-токен: прокидывание вернёт 403 (приложение это переживёт,
  локально письмо прочитанным станет, но в ящике нет).

Чтобы исправить: в боте `/accounts` → удалить Gmail-аккаунт → подключить заново.
Повторная авторизация выдаст токен с `gmail.modify`, и метка UNREAD будет
сниматься в самом Gmail.

## 10. Как работает эластичный интервал синхронизации

Интервал считается **отдельно для каждого аккаунта** по времени последнего письма:

```
интервал = max(10с, min(5 мин, пользовательский предел, (now - received_at) / 10))
```

- Только что пришло письмо → интервал сбрасывается на **10 секунд**.
- Почта «молчит» → интервал растёт пропорционально простою: 1 мин простоя → ~6с,
  10 мин → 60с, 30 мин → 180с, потолок **5 минут**.
- Новое письмо обнуляет простои → снова 10с.
- Ручной выбор интервала отсутствует — интервал полностью автоматический
  (минимум 10с, потолок 5 мин).

Ошибки синка не молотят провайдера: после сбоя интервал уходит в экспоненциальный
бэкофф (`60с, 120с, 240с, ...` с потолком), счётчик сбрасывается после успеха.
